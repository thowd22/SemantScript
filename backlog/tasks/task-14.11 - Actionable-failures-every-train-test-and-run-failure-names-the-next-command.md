## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The diagnostics catalogue lists every error with a cause and a fix, but the tools themselves do not say it: a verification failure prints the failing cases and stops, a runtime SemaRuntimeNotLoadedError says only that no artifact is loaded, and the trainer's Python tracebacks reach the terminal unwrapped when the interpreter or a package is missing. A developer should not need the catalogue to know what to do next.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Every verification failure line in the train report ends with a specific suggestion derived from the evidence: the constraint to add for a rule the misses share, an example for a repeated miss, more cases or epochs for a calibration failure, or the seed retry
- [ ] #2 Runtime errors for a missing or stale artifact name the command that fixes them, and the CLI wraps trainer and interpreter failures into one line with the doctor check to run
- [ ] #3 The diagnostics catalogue's fix column and the tools' messages are generated from one source so they cannot drift
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. One source (AC3). New diagnostics/remedies.json: every remedy the tools print, as entries {id, family, match (the catalogue's failure/class column), cause, fix}. fix is a template with {name} placeholders the tools fill from evidence; the docs render a placeholder as <name>. Families: verifier (gold-rule-constraint, gold-repeated-miss-example, gold-check-example, violation-example, violation-denser-data, calibration-cases-epochs, seed-retry-attempts, seed-retry-next-seed, type-no-cache), trainer-process (python-missing, module-missing per doctor check id trainer/model/torch/onnxruntime, python-too-old, trainer-crash), runtime (not-loaded, artifact-missing, one per ArtifactLoadError code, unknown-function/stale), cli (test-no-artifact, test-example-mismatch, test-function-absent, run-no-export, build-no-tsconfig, build-no-outdir). New scripts/generate-remedies.mjs writes runtime/src/remedies.generated.ts, trainer/src/semantscript_trainer/remedies_generated.py and the generated tables in docs/diagnostics.md between <!-- remedies:<family>:begin/end --> markers (prettier-padded), and with --check exits 1 naming each stale file. Drift tests: runtime/test/remedies.test.mjs runs --check (node CI job) and trainer/tests/test_remedies.py compares the generated Python module with the JSON (python CI jobs). Small formatters: remedy(id, params) in runtime/src/remedies.ts (exported from @semantscript/core for the CLI) and semantscript_trainer/remedies.py; both reject unknown ids and missing or extra params. Doctor check fixes and TS91xx compiler fixes stay hand-written (their tools do not print a catalogue fix); stated in the catalogue.
2. Verification suggestions (AC1), trainer/src/semantscript_trainer/verification.py + new remedies.py derivation helpers (pure, torch-free): VerificationResult gains suggestions: tuple[str, ...] (compare=False, not serialized to IR/manifest; empty or one per failure, validated). evaluate_training_result gathers structured evidence (gold misses: inputs/expected/predicted; corpus rows mispredicted the same way; constraint violations per constraint index with required output) and derives: (a) gold misses (>=2) sharing expected output and a single-field predicate (string/bool equality, numeric >= / <= threshold) that holds for every miss and every corpus row it covers is labelled that output, not already a constraint -> 'add always(() => order.status === "cancelled", "deny")'; (b) otherwise the most frequent teacher-labelled row mispredicted like a gold miss -> 'add examples entry { inputs: {...}, output: ... }'; else check the example against the teacher (explain is TASK-14.7 follow-up); (c) a constraint violated by >=2 records -> example literal with the output an always() demands (never(): the teacher label); single violations -> denser boundary data (--cases 2n, --counterfactual-ratio); (d) ECE -> --cases <2n> or --epochs <e+k> with current values; (e) type errors -> --no-cache.
3. Seed retry suggestion, trainer cli.py: after seed_retry_decision, a narrow failure that stopped because the retry was off or exhausted replaces the ECE/violation suggestion with seed-retry-attempts (--seed-attempts <k>) or seed-retry-next-seed (--seed <n+1>). _function_report/_attempt_report add verification.suggestions and each failure string in the report ends with '\n  next: <suggestion>' (so the JSON and the rendered report both end with it); the error: verification failed stderr line names the first suggestion. Test in trainer/tests/test_remedies.py (derivation units with synthetic rows) and test_seed_retry.py/test_cli.py (report shape) without torch where possible; a torch test for evaluate_training_result suggestions skips cleanly without the extra.
4. CLI render + trainer wrapping (AC2), cli/src/train.ts: renderTrainReport prints the suggestions (next: line after each failure block; tolerate reports without the field). runProcess pipes stderr: forwards lines live, buffers from 'Traceback (most recent call last):', and on a nonzero exit classifies the last exception line (ModuleNotFoundError name -> doctor check id trainer/model/torch/onnxruntime; SyntaxError/version -> python; other -> trainer-crash) into one line: 'semantscript train: the trainer stopped: <Exc: msg>; run semantscript doctor (check <id>) ...; full traceback in <report>.traceback.txt'. spawn ENOENT -> python-missing line with the doctor check. Same wrapping for --estimate's captured stderr. New fixture behaviour in cli/test/fixtures/fake_trainer.py (FAKE_TRAINER_RAISE=module:torch|crash) and cli tests.
5. Runtime (AC2): SemaRuntimeNotLoadedError message names loadSemaArtifact() and semantscript run and carries remedy; ArtifactLoadError gets readonly remedy (per code; missing artifact directory/ENOENT -> semantscript train; INCOMPATIBLE -> semantscript train; INVALID_POINTER/INTEGRITY/INVALID_JSON/INVALID_MANIFEST -> semantscript releases rollback <release> or train; RESOURCE -> semantscript doctor --runtime; QUOTA -> maximum*Bytes option) appended to message, plus readonly detail (message without the remedy) that cli/src/releases.ts RELEASE_REJECTED uses so a refusal does not advise rollback inside rollback; SemaUnknownFunctionError (stale: program rebuilt after training) names semantscript build then semantscript train. Existing regex assertions keep matching (messages only gain a suffix). Tests in runtime/test/artifact-loader.test.mjs and inference-runtime/runtime tests.
6. CLI test/run/build: test with no current.json -> test-no-artifact line (semantscript train, or --artifact); a replayed example mismatch and an absent function -> semantscript build && semantscript train; run with a missing export lists the exports; build: missing tsconfig -> semantscript init, missing outDir -> fix. All texts via remedy(). cli.test.mjs cases for each.
7. Docs: docs/diagnostics.md (generated fix columns for verifier gates, new trainer-process and CLI failure tables, runtime table; how the next: line is derived; note that remedies.json is the source and how to regenerate), cli-reference.md (train next: lines, traceback file, test/run messages), environment.md (wrapped trainer failure line), docs/CONTRIBUTING.md (npm/node scripts/generate-remedies.mjs, --check in tests), runtime/README.md (remedy/detail), trainer/README.md (verification.suggestions, failure strings), cli/README.md if it lists output. npx prettier@3.9.9 --check docs README.md.
