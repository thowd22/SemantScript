## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When a trained expression gives a wrong answer the developer has sema.withConfidence in code and the train report on disk, and nothing in between: no command shows the calibrated distribution for an input, which constraints and examples are active for it, the closest training cases and their labels, or whether the expression's artifact is even the current build. The editor plugin shows verified accuracy but cannot answer for one input.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 semantscript explain <module.js> --call <export> --input <json> prints the value, the calibrated distribution and confidence, every constraint active for the input with whether the answer satisfies it, the gold examples nearest to the input, and the nearest training cases from the cached datasets with their labels and origins
- [x] #2 The command says when the compiled function id is missing from the loaded artifact (changed since training) and which release and verification metrics the answer came from
- [x] #3 The diagnostics page documents a wrong-answer workflow that starts with explain and ends with the example or constraint to add
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Approach: trace the real call (not static export->id mapping; the bundle has no export map, only source path/line), force diagnostics while tracing, then join each observed call with the bundle (constraints, examples), the manifest (release, metrics, provenance) and the cache (the release's dataset and adversarial sidecar).

1. Runtime (runtime/src/artifact-runtime.ts, index.ts): add two additive LoadSemaArtifactOptions: `diagnostics: "always"` (buildInferencePlan sets diagnosticsRequired for every function; applyConfidencePolicy unwraps diagnostic.value for value-mode functions so program code sees the same values) and `observe(observation)` called for every dispatched call (call and callStage) with {functionId, inputs, resultMode, confidenceThreshold, diagnostic} and, before SemaUnknownFunctionError is thrown, {functionId, inputs, missing: true}. Export the SemaCallObservation type. Runtime tests: value function under diagnostics:"always" still returns the plain value and the observer gets the distribution; diagnostic-mode function unchanged; missing id observed then thrown; threshold below-confidence still throws SemaConfidenceError after observation. Document in runtime/README.md.
2. CLI predicate evaluator (cli/src/constraint-eval.ts): TypeScript port of constraints.py _evaluate semantics for the closed v1 AST (literal/input/property/index/unary/binary; && || require booleans; === !== strict with number equality; ordered compare numbers-or-strings by UTF-16; arithmetic finite-only, / and % by zero error; missing property -> undefined sentinel; string/array length and index rules; object index key via JS number string). Typed ConstraintEvaluationError; an erroring predicate is reported as "could not evaluate: <reason>", not a crash. Cross-language golden vectors in examples/constraints/predicate-vectors.v1.json (predicate, inputs, expected true/false/error) consumed by a Node test in cli/test and a Python test trainer/tests/test_predicate_vectors.py against evaluate_constraint_predicate, so both evaluators are pinned to the same semantics. Mention the vectors in examples/README.md.
3. CLI explain (cli/src/explain.ts): `semantscript explain [--artifact <root>] [--bundle <path>] [--cache-dir <dir>] [--neighbors <n>] [--json] <module.js> --call <export> (--input <json> | --input-file <path>)`. Reuse run.ts argument parsing (factor resolveArguments/module import into a shared helper exported from run.ts). Load artifact with {diagnostics:"always", observe}, call the export, collect observations; catch SemaUnknownFunctionError/SemaConfidenceError/other errors and still report what was observed. For each observed call print: function id, source path:line (bundle), value, confidence/uncertainty and the calibrated distribution (scalar) or per-field distributions (object), threshold outcome; each constraint whose predicate is active for the inputs with kind, source text, required/forbidden output and satisfied/violated by the answer (inactive count summarized; evaluation errors named); the nearest gold examples from the bundle definition with their outputs; the nearest training cases from the release's cached dataset (the datasets/v1 file whose sha256 equals the manifest trainingProvenance.datasetSha256; else newest dataset for the function id, flagged as not the release's) plus the adversarial sidecar whose payload.baseDataset.datasetSha256 matches, each with label and origin (gold / synthetic via teacher provider/model / adversarial constraint-boundary|counterfactual); release line: release dir, manifestSha256, createdAt, application id@version, teacher, base model, and the function's verification metrics (status, accuracy, ECE, Brier, pair consistency, attested cases, constraint violations, per-head accuracy). Distance: documented typed distance over the canonical JSON inputs = mean over the union of leaf paths of per-leaf distance (numbers |a-b| scaled by that leaf's range over candidates+query, strings 1 - word-set Jaccard, booleans/null/literals exact 0/1, a leaf missing on one side 1), ties by dataset order; default 5 neighbours. Missing id: print that the compiled function id is absent from the loaded artifact (the expression changed since training or the wrong artifact is loaded), still show constraints/examples from the bundle, list artifact functions not present in the bundle (the likely previous version) and name the fix (semantscript train). Bundle absent/stale: say so and skip constraints/examples. No observed call: say the export made no sema call. Diagnostic-mode function: value read from the diagnostic. Extend cli/src/manifest.ts summary with createdAt/teacher/baseModel/datasetSha256 (additive) rather than a second manifest reader. --json prints one document; exit 0 when explained (even if the answer violates a constraint), 1 when the export is missing, the call threw something other than a missing id/below-threshold, or an id is missing; 2 for usage errors.
4. Wire into cli/src/index.ts (COMMANDS, USAGE, exports).
5. Tests in cli/test/cli.test.mjs using runtime/test/fixtures/artifact.mjs: a bundle written for the fixture id with constraints (active satisfied, active violated, inactive, erroring) and examples; a scratch cache dir with a dataset document whose sha256 is put into the manifest via transformManifest plus an adversarial sidecar and a decoy dataset; assertions on value, distribution summing to 1, constraints, neighbour order and origins, release/metrics lines, --json shape; a missing-id case (module calling nf_9...); a diagnostic-mode function (transformManifest resultMode diagnostic); an export that makes no sema call. Add fixture module cli/test/fixtures/explain-module.mjs.
6. Manual check against /home/admin2/SemantScript/examples/express-app (read-only: point --artifact, --bundle, --cache-dir at it, run from the worktree) and record the output in notes.
7. Docs: docs/cli-reference.md (explain section, synopsis, exit codes), cli/README.md (explain section, command list), docs/diagnostics.md (new "Wrong-answer workflow" section: run explain -> read the release and whether the id is current -> check active constraints (violated => model/gate problem, retrain; none active => add an always/never constraint) -> compare nearest gold examples and training labels (wrong/sparse labels => add a gold example near the input or fix the constraint that labeled them) -> retrain -> explain again; plus a row for the missing-id message), docs/index.md (CLI line and diagnostics description), runtime/README.md for the options, docs/index.md component line for CLI commands. ## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Added semantscript explain <module.js> --call <export> --input <json>. It traces the real sema calls, using the new runtime options diagnostics:'always' and observe. For each call it prints the value, calibrated distribution and confidence, the constraints active for the input with satisfied/violated (evaluated by a TypeScript port of the trainer's predicate evaluator, pinned by 51 cross-language vectors in examples/constraints/predicate-vectors.v1.json), the nearest gold examples, the nearest training cases from the release's cached dataset and adversarial sidecar with labels and origins (distance: mean per-leaf typed distance), and the release, manifest digest, teacher, base model and verification metrics. It reports a compiled function id that is missing from the artifact and names the earlier artifact ids. Documented in docs/cli-reference.md, cli/README.md, docs/diagnostics.md (wrong-answer workflow), docs/index.md, runtime/README.md. Verified with build, lint:node, test:node (all green), pytest vectors, ruff, prettier, and manual runs against the Express example artifact.
