## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The verifier's constraint check (trainer/src/semantscript_trainer/verification.py: _constraint_violations, fed by _case_records over the reconstructed training corpus) counts violations only on records the model trained on: gold examples, teacher-labelled synthetic cases and the adversarial boundary pairs and counterfactual twins. The Express example's release 217d386c passed with 0 violations and yet answers review or approve for orders at 100, 110, 120, 150 and 200 days under always(() => order.ageDays > 90, 'deny') (semantscript explain in examples/express-app shows it; only the exact boundary cases at 90 and 91 days and the training cases at 132 days answer deny). The gate needs a held-out sample: inputs generated from the function's input types and its constraints' predicates (both sides of each boundary and the interior of each region, plus uniform draws), deterministic by seed, never overlapping the training corpus, scored under the raw model like the existing check, and subject to the same tolerance and seed-retry classification (TASK-14.6). Held-out benchmark inputs must never enter training. Relevant code: verification.py (_constraint_violations, _gate_failures, VerificationConfig.maximum_constraint_violation_rate), constraints.py (predicate evaluator, ConstraintEvaluationBudget), adversarial.py (boundary generation to reuse for sampling), dataset.py (canonical inputs), cli.py (report, seed retry), cli/src/train.ts and test-command.ts (report rendering), docs/training-pipeline.md, docs/diagnostics.md (generated remedies via diagnostics/remedies.json and scripts/generate-remedies.mjs), docs/cli-reference.md. No paid teacher calls are needed: the Express example's cached datasets under examples/express-app/.semantscript/cache allow free retrains, and the constraints teacher (--teacher constraints) trains the refund-service example at no cost.

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Findings: the verifier scores constraints only over _case_records (corpus rows + attested cases). adversarial.py boundary generation is teacher-driven (not reusable offline); the deterministic, predicate-aware sampler already exists as teachers/constraints.py ConstraintSampler (threshold facts, inferred ranges, single-field edits), but it refuses object outputs because it also labels. docs/training-pipeline.md does not exist yet. The manifest verification object is closed in schemas/application-artifact.v1.schema.json, runtime/src/artifact-loader.ts (exact keys), artifact-types.ts and cli/src/manifest.ts. VerificationConfig is part of the build-cache recipe, so a new setting invalidates old function records (intended: they carry no held-out evidence). The existing "held-out acc" column means the evaluation split, so the new figure is named "held-out constraints" / heldOutConstraints everywhere to avoid confusion.

1. Sampler reuse: in teachers/constraints.py let ConstraintSampler be built with labels=False (skips the scalar-output/support requirement only; teacher streams and cached datasets unchanged).
2. New module trainer/src/semantscript_trainer/held_out.py: HeldOutSampleConfig (size, default 512, bounded 1..50_000) and sample_held_out_inputs(ir, *, size, seed, exclude) -> HeldOutSample (inputs, per-constraint coverage counts, seed). Per constraint: boundary pairs (near-threshold draw + single-field edit that flips the predicate, both sides kept), interior draws on each side (uniform draw, predicate side matched, numeric paths away from every threshold), then uniform draws for the rest. Streams seeded from sha256("semantscript.held-out/v1", seed, function id, constraint, category); dedup and disjoint from the canonical encodings of every corpus row, gold example and attested case; inputs that fail predicate evaluation or canonical encoding are skipped. Draw cap = size x fixed factor; before sampling, compiled.ensure_evaluation_budget(draw cap + size) and one shared ConstraintEvaluationBudget; exceeding it raises VerificationConfigurationError naming --held-out-samples. Coverage shortfall (a side no draw reached) is recorded, not fatal.
3. verification.py: VerificationConfig.held_out_samples (default 512); evaluate_training_result(..., held_out_seed=None -> training seed) samples, predicts the held-out inputs with the raw model in the same _collect_predictions pass (no labels), evaluates evaluate_output_contract per input, and builds HeldOutConstraintEvidence(sample_size, violating_inputs, violations, seed, coverage, details). New gate "held-out": rate = violating inputs / sample size vs maximum_constraint_violation_rate; failure text names each broken constraint (index + source), up to 10 offending inputs with the model's answer, the seed and that the inputs are outside the training corpus. seed_retry_decision classifies the held-out rate exactly like the corpus rate (zero tolerance stops, within margin retries). VerificationResult gains held_out (validated; passed results may carry tolerated violations); to_manifest_function_verification adds verification.heldOutConstraints {sampleSize, violations, violationRate, seed}.
4. Suggestions/remedies: two distinct verifier remedies in diagnostics/remedies.json (held-out-violation-example when one admissible output exists: paste the offending input as an examples entry and rerun; held-out-violation-more-cases otherwise: rerun with --cases N), regenerated with node scripts/generate-remedies.mjs (runtime/compiler/trainer generated files + docs/diagnostics.md); suggestions.held_out_suggestion.
5. cli.py: --held-out-samples flag -> VerificationConfig; held_out_seed = the build's first --seed so every seed retry faces the same sample; function report verification.heldOutConstraints, attempt report heldOut fields, log line; build_cache stores/restores the held-out evidence in the function record (optional on read).
6. Manifest contract: optional verification.heldOutConstraints in schemas/application-artifact.v1.schema.json, runtime artifact-loader validation + artifact-types.ts, cli/src/manifest.ts summary (null for older releases). docs/ir-and-artifact-reference.md.
7. Node CLI: "held-out-samples" passthrough in cli/src/train.ts; train report table and attempts table get a held-out column (v/n, "-" for old reports); cli/src/table.ts VERIFICATION_HEADERS/verificationCells get the held-out column so semantscript test and releases show display it without touching test-command.ts (15.3) or releases.ts (15.5). Update cli/test/fixtures/fake_trainer.py and cli tests (attempt-table regex).
8. Tests: trainer/tests/test_held_out.py (per-constraint boundary both sides + interior coverage on the refund IR, determinism by seed and change with seed, disjointness from an exclusion set, object-output IR, budget refusal and aggregate string budget); test_verification.py (memorising fixture model: 0 corpus violations, fails the held-out gate with constraint, inputs, answer and generated remedy; tolerance admits; manifest projection); test_seed_retry.py (held-out narrow/zero-tolerance classification); test_cli.py (report + manifest carry heldOutConstraints, cache round trip); runtime loader test for the optional field; cli render tests. Adjust existing fakes (FixedTokenizer default token) where held-out inputs now reach them.

Real reproduction (AC2): copy examples/express-app bundle + .semantscript/cache + teacher.toml from the main checkout into the scratchpad, retrain seed 5 with the reduced-prompt recipe on GPU from cached datasets (dummy ANTHROPIC_API_KEY and --max-cost-usd 0.01 so a cache miss cannot spend), confirm the gate fails naming constraint 0 (order.ageDays > 90 -> deny) with offending inputs and the next command; also train examples/refund-service with --teacher constraints to show the passing path and the manifest figures.
