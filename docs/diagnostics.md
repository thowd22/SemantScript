# Diagnostics catalogue

Every error SemantScript raises falls into one of four families: compiler
diagnostics at a `sema` site, editor warnings from the language-service
plugin, trainer and verifier failures during `semantscript train` (including
its environment preflight), and runtime
errors thrown by compiled calls. This page lists each with its cause and the
fix. A trained expression that answers wrongly raises no error at all; the
[wrong-answer workflow](#wrong-answer-workflow) at the end takes one from
`semantscript explain` to the example or constraint to add.

## Compiler diagnostics (`TS9100` to `TS9131`)

Every diagnostic names the file, line and column of the `sema` site, the code,
the message and the site text, in TypeScript's own format, so `tsc`, the
build-tool adapters and the editor plugin all show the same thing:

```text
src/refunds.sem.ts(34,86): error TS9122: src/refunds.sem.ts:30:10: constraint predicates support only literals, input/property/index access, comparisons, boolean operators, and finite-number arithmetic (site: sema<RefundDecision>({ … })`…`)
```

| Code | Family                    | Cause                                                                                                                                                                                                                                                                                                                               | Fix                                                                                                                                                                              |
| ---- | ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 9100 | malformed site            | A `sema` or `sema.withConfidence` tag that is not a canonical site: no output type argument, two type arguments, a configured call with zero or several options arguments, or use through optional chaining (`sema?.`).                                                                                                             | Write `sema<T>\`…\``or`sema<T>({ examples, constraints })\`…\`` with exactly one type argument and, when configured, exactly one inline options object.                          |
| 9101 | unsupported output        | `T` is not a finite scalar: `string`, `number`, `any`, a single literal, an array, a nullable, a union with an unsupported member.                                                                                                                                                                                                  | Use `boolean`, a union of two or more string literals, a homogeneous enum, `Ordinal<[…]>`, `BoundedInt<Min, Max>`, `BoundedNumber<Min, Max, Step>` or a flat interface of those. |
| 9102 | invalid enum              | The enum mixes string and numeric members, or has computed or duplicate values.                                                                                                                                                                                                                                                     | Make every member a constant of one primitive base with distinct values.                                                                                                         |
| 9103 | invalid ordinal           | `Ordinal` without exactly one tuple argument, a tuple of fewer than two members, or members that are not distinct string literals.                                                                                                                                                                                                  | `Ordinal<["low", "medium", "high"]>`: a fixed tuple of at least two distinct string literals.                                                                                    |
| 9104 | invalid bounds            | `BoundedInt`/`BoundedNumber` with minimum not below maximum, a non-integral `(Max - Min) / Step`, a non-finite member or more than 100,000 values.                                                                                                                                                                                  | Choose literal bounds and a step that divide the range exactly into a finite grid of at most 100,000 values.                                                                     |
| 9105 | invalid flat output       | An interface property is optional, a method, an index signature, a nested object, an array, a tuple, `null` or `undefined`, or the interface has no properties.                                                                                                                                                                     | Keep the interface one level deep with required scalar properties of the kinds above, or split it into separate expressions.                                                     |
| 9110 | invalid interpolation     | An interpolation that is not a bare identifier (`${item.value}`, `${f(x)}`, `${a + b}`).                                                                                                                                                                                                                                            | Assign the expression to a named `const` first and interpolate the name; the name becomes the input's name in the IR.                                                            |
| 9111 | duplicate interpolation   | The same identifier is interpolated twice in one template.                                                                                                                                                                                                                                                                          | Interpolate each input once; repeat it in the prose by name instead.                                                                                                             |
| 9112 | unsupported input         | An input whose type cannot be serialized: a function, a class instance with methods, a database client, a recursive type, `unknown`, a symbol, or an object with an index signature.                                                                                                                                                | Pass plain data (primitives, literals, enums, arrays, tuples, objects, unions of those). Read rows first and hand the expression the values.                                     |
| 9120 | invalid options           | The options argument is not an inline object literal, or has a key other than `examples` and `constraints`.                                                                                                                                                                                                                         | `sema<T>({ examples: […], constraints: […] })` with both arrays inline; move shared data into the arrays, not into variables.                                                    |
| 9121 | invalid example           | An example's `inputs` does not cover every interpolated input exactly once, or its `output` is not assignable to `T`.                                                                                                                                                                                                               | Give each example every input by name with a value of the input's type and an output from the support.                                                                           |
| 9122 | invalid constraint        | A constraint is not a direct `always(() => …, output)` or `never(…)` call; its predicate uses something outside literals, input/property/index access, comparisons, boolean operators and finite arithmetic (a function call, a template, a regex); its output is not in the support; or the output is a complete flat interface.   | Rewrite the predicate over the inputs only; inline helpers such as tier windows as boolean arithmetic; for an interface, constrain per-field expressions instead.                |
| 9123 | invalid `@confidence`     | The header is repeated, or is not `@confidence(q)` with a decimal `q` in `[0, 1]`.                                                                                                                                                                                                                                                  | One `@confidence(0.8)` line among the header lines before the behavior text.                                                                                                     |
| 9124 | empty behavior            | The template has no text once headers, interpolations and whitespace are removed.                                                                                                                                                                                                                                                   | Write the behavior: what the expression decides and from what.                                                                                                                   |
| 9125 | contradictory constraints | An `always` and a `never` with the same predicate name the same output.                                                                                                                                                                                                                                                             | Remove one; the pair can never be satisfied.                                                                                                                                     |
| 9126 | invalid `@domain`         | The header is repeated, or is not `@domain(name)` with a lowercase name of letters, digits and dashes.                                                                                                                                                                                                                              | One `@domain(fraud)` line, or drop it and let the file or controller name the domain.                                                                                            |
| 9130 | compilation configuration | The build itself, not a site: `TypeScript skipped JavaScript emission` or `TypeScript emitted no JavaScript output` (the tsconfig has `noEmit`, `emitDeclarationOnly`, or excludes the `.sem.ts` files), a `--domain-depth` whose name is not lowercase letters, digits and dashes, or whose depth is not a positive integer.       | Let the project emit JavaScript for the `.sem.ts` files and fix the option; the message names it.                                                                                |
| 9131 | execution plan            | Provenance analysis failed: `SEMA_EXECUTION_PLAN_CYCLE` (an initializer cycle, or a sema expression that feeds itself through locals), `SEMA_EXECUTION_PLAN_BUDGET` (a data-flow chain deeper than 100 levels or more than 100,000 units of work), or `SEMA_EXECUTION_PLAN_INVALID` (a routed plan whose domains are inconsistent). | Break the cycle or the chain (route the value through a function call, which the analysis does not follow), or simplify the routing.                                             |

One fixture per family is rendered in the compiler's snapshot test
(`compiler/test/fixtures/diagnostics.snapshot.txt`), which is the canonical
wording.

## Editor warnings (`9150` to `9153`)

The language-service plugin adds warnings at a site from the latest artifact:

| Code | Cause                                                                          | Fix                                                                                         |
| ---- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| 9150 | No trained artifact under `.semantscript/artifact` (or the `artifact` option). | Run `semantscript train` (or `dev`).                                                        |
| 9151 | The expression changed since training, so its id is not in the artifact.       | Train again; the build cache retrains only this head.                                       |
| 9152 | Verified accuracy below `accuracyThreshold` (default 0.95).                    | Add examples for the misses, or a constraint for a broken rule; consider `@confidence`.     |
| 9153 | Verified ECE above `eceThreshold` (default 0.1).                               | More cases, or a confidence threshold with a fallback so low-confidence answers are caught. |

## Trainer and verifier failures

Before the bundle driver starts, `train` runs the environment preflight: the
`semantscript doctor` checks for the interpreter, the trainer packages,
PyTorch and its device, ONNX Runtime, the platform environment and the
teacher, without a billed request. A failed check stops the command with exit
1 and `semantscript train: stopped before training`, and the failing line
carries its fix (`--no-preflight` skips it). The
[environment guide](environment.md) lists every check with its causes and
fixes; the common ones:

| Failing check    | Typical cause                                                                                                                                                                                                                                         | Fix                                                                                                                             |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `python`         | `python3` (`python` on Windows, or `--python`, `SEMANTSCRIPT_PYTHON`) is not on the path or is older than 3.12.                                                                                                                                       | Install Python 3.12, or point the CLI at one.                                                                                   |
| `trainer`        | The interpreter cannot import `semantscript_trainer` (CLI run outside the checkout without the package).                                                                                                                                              | `pip install "semantscript-trainer[training]"` into that interpreter (in a clone: `pip install -e ".[training]"`).              |
| `torch`          | The training extra is missing, or packages in the user site break Transformers (`numpy.long`).                                                                                                                                                        | Install the extra; with `platform-env` failing too, `export PYTHONNOUSERSITE=1`.                                                |
| `platform-env`   | An environment variable the imports or the GPU need is not set; doctor proved it by retrying with it.                                                                                                                                                 | The printed `export …` line, also in the shell profile (on Windows: the PowerShell or cmd line, then `setx`).                   |
| `teacher-config` | No teacher file and no `ANTHROPIC_API_KEY`, or an invalid `[teacher]` table.                                                                                                                                                                          | Write the TOML ([teachers](teachers.md)), set the key, or pass `--teacher constraints` when the constraints decide every input. |
| `teacher-key`    | `ANTHROPIC_API_KEY` (or `ANTHROPIC_AUTH_TOKEN`) is unset for an Anthropic teacher or an Anthropic `[teacher.fallback]` (Ollama and the constraints teacher need no key); with an OpenRouter `base_url` and only `OPENROUTER_API_KEY` set, it says so. | `export ANTHROPIC_API_KEY=…` (`"$OPENROUTER_API_KEY"` for the OpenRouter route); on Windows the PowerShell and cmd forms.       |
| `teacher-probe`  | The Ollama server is down or lacks the model (the constraints teacher is never probed; its fallback is).                                                                                                                                              | `ollama serve`, or `ollama pull <model>`.                                                                                       |

After the preflight, `semantscript train` exits 1 and prints the reason. The bundle driver
(`TrainBundleError`) refuses a malformed bundle before anything runs:

| Message                                                                                                                                                          | Cause and fix                                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bundle must be a semantscript.ir-bundle version 1 document`, `bundle must contain at least one neural function`, `bundle functions must have unique string ids` | The bundle file is not the compiler's output; point `--bundle` at the build's `semantscript.ir.v1.json`.                                                                                 |
| `<id> is not a source-stage record`, `<id> has no model binding`                                                                                                 | An edited or already-trained record was passed; rebuild.                                                                                                                                 |
| `cases must be a non-negative integer`                                                                                                                           | `--cases` is malformed.                                                                                                                                                                  |
| `teacher must expose a TeacherDescriptor`                                                                                                                        | A custom teacher (a Python `Teacher`) lacks its identity; give it a `descriptor`.                                                                                                        |
| `<id> declares constraints; the teacher must support boundary and counterfactual generation`                                                                     | Constraints need an `AdversarialTeacher`; the Anthropic, Ollama and constraints backends are; a custom one must implement both methods.                                                  |
| `<source>:<line> (<id>) has no gold examples: verification needs at least one attested example per expression, whatever the teacher`                             | Checked before any generation: add an `examples: [{ inputs, output }]` entry to the `sema` call. Verification checks the artifact against the gold examples, so every teacher needs one. |
| `--teacher is required: no … found and ANTHROPIC_API_KEY is not set`                                                                                             | No teacher file and no key; write a `[teacher]` TOML, set the key, or pass `--teacher constraints` when the constraints decide every input.                                              |

The built-in constraints teacher (`--teacher constraints` or
`backend = "constraints"`, see [teachers](teachers.md)) stops with a
`TeacherConfigurationError` naming the expression as `<source>:<line> (<id>)`:

| Message                                                                                                                                                                                     | Cause and fix                                                                                                                                                                                                                                                                                                                                                          |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `the constraints do not decide every input, so the constraints teacher cannot label it alone. For the input {…} the constraints admit "a", "b"`                                             | The constraints leave that input open. Add `always`/`never` constraints until exactly one output is admissible for every input, or label the inputs they leave open with a language-model teacher: a teacher TOML with `backend = "constraints"` and a `[teacher.fallback]` table, passed with `--teacher <file>` (the `constraints` keyword cannot carry a fallback). |
| `the constraints contradict each other on an input … admit no output`                                                                                                                       | Two active constraints require different outputs (or forbid every one) for the input shown; fix the predicates.                                                                                                                                                                                                                                                        |
| `it declares no constraints, so the constraints teacher cannot label it`                                                                                                                    | Use a language-model teacher for that expression, or a teacher TOML with `backend = "constraints"` and a `[teacher.fallback]` table, passed with `--teacher <file>`.                                                                                                                                                                                                   |
| `its output is an object, and the constraints label scalar outputs`                                                                                                                         | Object outputs need a language-model teacher (or a `[teacher.fallback]`).                                                                                                                                                                                                                                                                                              |
| `found <k> of <n> distinct inputs that the constraints decide and that one field edit moves to another output …` (or `… the constraints decide …` without the twin filter)                  | The sampled inputs are too narrow, or (with `twin_filter`) no input has a single-field twin with another label, as for an expression that always answers the same. Write a TOML with `backend = "constraints"` and `[teacher.ranges]` or `twin_filter = false`, and pass it with `--teacher <file>`.                                                                   |
| `<source>:<line> (<id>) needs at least two independent row groups, but its <n> training rows (<k> distinct inputs) form one`                                                                | The held-out split keeps identical inputs, and each case with its counterfactual twin, together; in a small input space they link every row. Lower `--counterfactual-ratio` (0.5, or 0 when the inputs are a few booleans or enum values), request fewer `--cases`, or widen `[teacher.ranges]` for the constraints teacher.                                           |
| `warning: <source>:<line> (<id>): only <k> distinct inputs among <n> cases`                                                                                                                 | Not an error: the teacher repeated inputs to reach `--cases` because the input space is small, so held-out accuracy covers fewer inputs than the count suggests. Widen `[teacher.ranges]` or request fewer cases.                                                                                                                                                      |
| `the constraints could not build this case, and the [teacher.fallback] teacher (<provider>/<model>) proposed …`                                                                             | Mixed mode: the fallback's boundary pair or twin changes more than one field, misses the predicate, or is decided back to the anchor's output. Local models often fail here; lower `--counterfactual-ratio` (0 works), use a stronger fallback, or complete the constraints.                                                                                           |
| `<source>:<line> (<id>): IR gold example <i> is invalid: case output violates …`                                                                                                            | A gold example contradicts the expression's own constraints; fix the example or the constraint.                                                                                                                                                                                                                                                                        |
| `unknown constraints teacher configuration keys: … (valid keys: …)`, `unsupported teacher backend 'x'; expected anthropic, ollama or constraints`                                           | A misspelled key or backend in the TOML.                                                                                                                                                                                                                                                                                                                               |
| `ranges must be a [teacher.ranges] table`, `range low must be below high`, `range <name> needs low and high`, `the fallback teacher must be a language-model backend (anthropic or ollama)` | A malformed `[teacher.ranges]` or `[teacher.fallback]` table; see the TOML reference in [teachers](teachers.md).                                                                                                                                                                                                                                                       |

Teacher errors (`TeacherConfigurationError` for a bad TOML or an unsupported
backend, `TeacherTransportError` for a network or API failure,
`TeacherResponseError` for a response that fails the case schema,
`TeacherBatchError`/`TeacherBatchTimeout` for a Message Batch that did not
complete) abort generation rather than producing a partial dataset; a
malformed response is retried up to the adversarial `maximum_attempts` for
boundary and counterfactual proposals, and a synthetic case whose label
violates an active constraint is replaced (three rounds at most) before
`TeacherResponseError` names the constraint. `UnsynthesizableConstraintError` means
a constraint has no reachable two-sided boundary pair (its predicate is
constant, or no single-field edit crosses it): rewrite the predicate over the
inputs so both sides are reachable.

Teacher spend (`semantscript train --estimate`, `--max-cost-usd` and
`semantscript teacher probe`, see
[teachers](teachers.md#cost-estimate-and-spend-cap)):

| Message                                                                                                                                                                                                          | Cause and fix                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `error: spend cap USD <cap> reached: the next request (about USD <x>) would take the run from USD <y> past it after <n> paid request(s). Every dataset finished before the stop stays cached … rerun …` (exit 1) | `TeacherBudgetExceeded`: the run was stopped before the request that would pass `--max-cost-usd`. Finished datasets are cached, and with the Anthropic backend every paid response and every submitted batch is in the journal (a priced Ollama endpoint has no journal). Check `semantscript train --estimate`, then rerun with a higher cap or none; the journaled responses replay at no cost (the run line counts them as replayed). |
| `no price is known for teacher model '<model>'; add a [teacher.pricing] table with input_usd_per_million and output_usd_per_million`                                                                             | `TeacherPriceUnknown`: the model is not in the pinned Anthropic table and not on OpenRouter's list. Add the table to the teacher TOML. Without a cap or `--estimate` the run continues with a `warning:` and counts tokens but not dollars.                                                                                                                                                                                              |
| `unknown [teacher.pricing] keys: …`, `[teacher.pricing] <key> must be a non-negative finite number`                                                                                                              | A misspelled or negative price; the valid keys are `input_usd_per_million`, `output_usd_per_million`, `cache_read_usd_per_million`, `cache_write_usd_per_million` and `seconds_per_request`.                                                                                                                                                                                                                                             |
| `--max-cost-usd must be a positive number of USD` (exit 2)                                                                                                                                                       | The cap is zero, negative or not a number.                                                                                                                                                                                                                                                                                                                                                                                               |
| `--max-cost-usd <cap> is below the expected USD <x>: the run will stop before it finishes` (an `--estimate` line)                                                                                                | Not an error: the cap would stop the run partway. Raise it, or accept a partial run and resume later from the journal.                                                                                                                                                                                                                                                                                                                   |
| `note: the teacher's answers were rejected, so the <n> journaled response(s) this run used were discarded …`                                                                                                     | The run failed because the generator rejected the teacher's answers (a case outside the contract, a boundary pair that is not two-sided, a twin that breaks a constraint). The journal entries the run used are dropped so the rerun asks the teacher again; nothing else to do.                                                                                                                                                         |
| `teacher probe` ends `failed` with a fix (exit 1)                                                                                                                                                                | The one probe request failed, or was not sent: a missing key is reported as `no request sent: ANTHROPIC_API_KEY is not set` with the doctor's `teacher-key` fix (for OpenRouter, `export ANTHROPIC_API_KEY=$OPENROUTER_API_KEY`); otherwise the same causes and fixes as the doctor's `teacher-probe` check above (the model name, the network or the Ollama server).                                                                    |
| `no teacher to probe` (exit 2)                                                                                                                                                                                   | No teacher file and no `--teacher`; run `semantscript init --teacher …` or pass `--teacher`.                                                                                                                                                                                                                                                                                                                                             |

Verification (`VerificationGateError`) fails a function with one line per
gate, each followed by the first failing cases with inputs, expected and
predicted values:

| Failure                                                                                        | Cause                                                                                           | Fix                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `N gold/human example prediction(s) failed`                                                    | The trained model contradicts a gold example or an external attested case.                      | Check the example is right; add nearby examples; more cases or epochs; a constraint if a rule is being missed. The seed retry never retries a gold miss.                                                                                                                                                                |
| `N adversarial constraint check(s) failed (r of M records exceeds the configured tolerance t)` | Raw predictions violate an active `always`/`never` on more than the tolerated share of records. | A rate within `--seed-retry-margin` times a nonzero tolerance retries with the next seed on its own (below). Otherwise sample the corpus more densely around the threshold (numbers close to a boundary are the usual miss), train longer, or record a tolerance with `--max-constraint-violation-rate` per decision-8. |
| `N output type check(s) failed`                                                                | A decoded prediction was outside the support; only possible with a corrupted head.              | Retrain with `--no-cache`.                                                                                                                                                                                                                                                                                              |
| `ECE x exceeds configured threshold t`                                                         | Calibration error after temperature scaling is above the gate.                                  | An ECE within `--seed-retry-margin` times the threshold retries with the next seed on its own (below). Otherwise more calibration rows (`--evaluation-ratio`, `--cases`), fewer epochs, or a higher `--ece-threshold` if the application tolerates it.                                                                  |

The seed retry ([CLI reference](cli-reference.md#seed-retry)) reads these
gates after every training attempt and logs one of:

| Line                                                                                                                                               | Meaning                                                                                                                                          | Fix                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `verification failed narrowly at seed <n> (<id>: violation rate r (v of M) within m x tolerance t …); retrying with seed <n+1> (attempt k of K) …` | Every failed gate was the violation rate or the ECE, within the margin. The next seed trains on the cached datasets; no teacher request is sent. | Nothing. The report's `attempts[]` lists every attempt; a build that needs several seeds every time is sensitive to its seed, and denser boundary data (above) makes it robust. |
| `not retrying: <id>: N gold/human example prediction(s) failed; a gold miss is not a seed effect …`                                                | A gold or human example was missed; another seed does not fix a contradiction between the example and the teacher's labels.                      | As for the gold failure above.                                                                                                                                                  |
| `not retrying: <id>: N output type check(s) failed`                                                                                                | A decoded prediction was outside the support.                                                                                                    | As for the type failure above.                                                                                                                                                  |
| `not retrying: <id>: violation rate r (v of M) is outside the retry margin m x t = …` or `… ECE x is outside the retry margin …`                   | The miss is wider than the margin.                                                                                                               | Fix the data or the recipe as above; `--seed-retry-margin` (at most 10) widens the margin when the gate is known to be seed-sensitive.                                          |
| `not retrying: <id>: N constraint violation(s) under a zero tolerance; the margin only widens a nonzero --max-constraint-violation-rate`           | The default tolerance is 0, and m x 0 is 0.                                                                                                      | Fix the data, or record a tolerance with `--max-constraint-violation-rate` (decision-8).                                                                                        |
| `not retrying: all K seed attempts failed (seeds a to b); the last failure was narrow: …`                                                          | Every attempt failed narrowly.                                                                                                                   | Raise `--seed-attempts` (at most 20), or make the data robust as above.                                                                                                         |
| `not retrying: seed retry is off (--seed-attempts 1), though the failure was narrow: …`                                                            | The retry is off.                                                                                                                                | Drop `--seed-attempts 1`, or rerun with the next `--seed` by hand.                                                                                                              |
| `not retrying: seed <n> is the largest seed a split accepts`                                                                                       | The next seed would pass 2^63 - 1, the largest held-out split seed.                                                                              | Start from a smaller `--seed`.                                                                                                                                                  |
| `not retrying: <id>: the violation rate's record count is unknown` or `not retrying: <id>: failed a gate the retry does not classify`              | A defensive stop: the result lacks what the margin needs, or failed a gate the retry cannot classify. Neither is expected from `train`.          | Report it as a bug with the train report attached.                                                                                                                              |
| `error: --seed-attempts: seed attempts must be an integer from 1 through 20` or `error: --seed-retry-margin: seed retry margin must be …` (exit 1) | An out-of-range `--seed-attempts` or `--seed-retry-margin`, checked before the bundle is read (`--estimate` included).                           | Pass a value in range.                                                                                                                                                          |

The same stop reason ends the `error: verification failed for <id>; not
retrying: …` line and is the report's `retry.stopReason`; the rendered
report prints `seed retry stopped: <reason>`, and after a retry that passed,
a `training attempts:` table (seed, status, accuracy, violations and ECE per
attempt) and `seed retry: published seed <n> after <k> attempts`. The
published release's manifest records the seed that passed as
`functions[].trainingProvenance.seed`, and `semantscript test` shows it in
its `seed` column.

`VerificationConfigurationError` (`verification requires at least one attested
gold or external case`, `temperature fitting requires held-out calibration
rows`, external cases not disjoint from training inputs) means the corpus
cannot form a closed evidence set: add at least one gold example to the
expression, keep the evaluation ratio above zero, and never attest inputs the
teacher also generated.

Export (`ArtifactExportError`) refuses weights changed after verification or a
tokenizer whose bytes differ; `ArtifactPublicationError` names a filesystem
problem under the artifact root (a symlink, a path outside the release, a
release directory that already exists with different content). Training
(`TrainingConfigurationError`, `TrainingExecutionError`) rejects an unsafe
recipe (a checkpoint above the trainable-parameter guard, a batch that cannot
fit) or a device failure; the message names the setting.

## Release management errors

`semantscript releases` refuses a switch or prune with exit status 1 and a
message that starts with one of `POINTER_INVALID`, `RELEASE_NOT_FOUND`,
`RELEASE_AMBIGUOUS`, `RELEASE_ALREADY_CURRENT`, `RELEASE_NO_PREVIOUS`,
`RELEASE_INTEGRITY`, `RELEASE_UNVERIFIED`, `RELEASE_REJECTED` or
`RELEASE_INVALID`. The [CLI reference](cli-reference.md#releases) gives each
cause; nothing is changed when one is reported.

## Packaging errors

`semantscript package` fails with exit status 1 and a message that starts
with one of `PACKAGE_NO_PROJECT`, `PACKAGE_NO_DIST`, `PACKAGE_NO_RELEASE`,
`PACKAGE_OUT_EXISTS`, `PACKAGE_INCLUDE_MISSING`, `PACKAGE_INSTALL_FAILED`,
`PACKAGE_NO_BINDING` or `PACKAGE_BINDING_LOAD_FAILED`, or with the release
codes above when the current release fails the checks `releases promote`
applies; the output directory is left as it was. `PACKAGE_OVER_TARGET` also
exits 1 but writes the bundle and lists the size levers that would fit. The
[CLI reference](cli-reference.md#package) gives each cause and
[Deploying](deploy.md#the-size-levers) the levers.

## Runtime errors

Compiled calls throw typed errors with a `code`. All are synchronous from the
program's perspective except artifact loading.

| Class                                          | `code`                                                                                                                                         | Cause                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Fix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

## Wrong-answer workflow

A wrong answer from a trained expression is not an error: the call returns a
valid value from the output type, and the release passed its gates. Start
from the input that answered wrongly and let `semantscript explain` show why:

```sh
semantscript explain dist/refunds.sem.js --call decideRefund \
  --input '[{"tier":"standard","priorRefunds":0},{"ageDays":120,"status":"fraudulent","total":80}]'
```

Against the Express example's release, this printed (abridged):

```text
call 1: nf_957c2b2b… (src/refunds.sem.ts:21)
  value        "review"
  confidence   0.9532, uncertainty 0.1957
  distribution "review" 0.9532 | "deny" 0.0355 | "approve" 0.0114
  constraints  2 active of 6 (4 inactive)
    always "deny" when order.ageDays > 90: VIOLATED by the answer
    never "approve" when order.status === "fraudulent": satisfied
  gold examples nearest the input (3 of 3)
    0.209  "review"  {"customer":{…},"order":{"ageDays":3,"status":"fraudulent","total":40}}
    0.437  "approve"  {"customer":{…},"order":{"ageDays":12,"status":"paid","total":88.5}}
    0.876  "deny"  {"customer":{…},"order":{"ageDays":70,"status":"paid","total":900}}
  training cases nearest the input (5 of 394; the release's dataset caa8e8954f69… plus its adversarial sidecar, 2 other cached datasets for this id)
    0.025  "deny"  adversarial constraint-boundary  {… "ageDays":95,"status":"fraudulent" …}
    0.029  "deny"  synthetic (anthropic/claude-sonnet-5)  {… "ageDays":132,"status":"fraudulent" …}
    0.029  "deny"  adversarial counterfactual  {… "ageDays":132,"status":"fraudulent" …}
    0.029  "review"  adversarial constraint-boundary  {… "ageDays":90,"status":"fraudulent" …}
    0.033  "deny"  synthetic (anthropic/claude-sonnet-5)  {… "ageDays":91,"status":"fraudulent" …}
  verification passed: accuracy 0.9241, ECE 0.0719, … 0 constraint violations
```

Read it top to bottom:

1. **Is this the release you think it is?** The `release` line names the
   release directory, build time and manifest digest, and each call its
   dataset, teacher and base model. A `missing` line means the compiled id is
   not in the loaded artifact: the expression changed since training (or the
   wrong artifact is loaded), so the answer you saw came from nowhere you can
   fix by editing examples. Run `semantscript build` and `semantscript train`,
   then explain again.
2. **Did an active constraint lose?** A `VIOLATED` constraint is a rule you
   already wrote that the model has not learned for this input. The training
   cases near the input show whether it had evidence: in the output above
   every nearest case past 90 days is labelled `deny` (the one `review` is the
   boundary case at exactly 90 days, where the constraint is inactive), so the
   data was right and the model generalised badly past the gold example at
   distance 0.209 that says `review` for a fraudulent order. Add this input as a gold example with the
   output the constraint requires, so verification must reproduce it; train
   with more cases or epochs; and read the verifier's constraint-violation
   rate for the function in the train report.
3. **No constraint covers the input?** When the answer is wrong under a rule
   that decides the input on its own (an amount, a status, a date), write the
   rule down: `always(() => …, output)` or `never(() => …, output)` in the
   `sema` options. The trainer rejects every teacher label that contradicts an
   active constraint and adds boundary cases on both sides of it, so the rule
   reaches the data, not just the prompt. The `could not be evaluated` lines
   name predicates that fail for this input (a missing field, a non-number in
   arithmetic); fix those first.
4. **Are the nearest labels wrong?** Training cases near the input with the
   label you did not expect mean the teacher reads the prompt differently from
   you there: `synthetic (<teacher>)` names who labelled them, and an
   `adversarial counterfactual` pair shows which single field edit flipped the
   label. Add a gold example at this input (and one on the other side of the
   boundary you mean), tighten the prompt text, or add the constraint from step 3. A large
   distance to every gold example says the input is outside what you
   attested; a gold example here is the cheapest fix.
5. **Is the answer just uncertain?** A low confidence with a spread
   distribution is the model saying it does not know. Beyond more examples,
   `@confidence(q)` with a fallback lets the application decide such inputs
   itself; explain reports whether the answer met the threshold.
6. **Retrain and check.** `semantscript train` (the cache reuses every
   unchanged dataset), then run the same `explain` again, and
   `semantscript test --bundle …` to replay every gold example, including the
   one you just added, through the new release.

"Nearest" in explain is a typed distance over the JSON inputs (numbers scaled
by each field's spread, word overlap for strings, exact match otherwise), not
the model's own similarity, so it finds the labelled cases that look most like
the input rather than the ones the model thinks are alike.
